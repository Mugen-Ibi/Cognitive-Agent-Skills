# Lite protocol

Use for low-stakes, reversible work where speed has more value than exhaustive verification.

## Sequence

1. **Intent** — identify the actual outcome and preserve explicit constraints.
2. **Quick reframe** — check for at most three hidden assumptions or alternate framings that could change the answer.
3. **Explore** — consider two to four materially different approaches when alternatives are useful.
4. **Sanity check** — test the leading answer for obvious contradictions, missing constraints, and failure modes.
5. **Compress** — lead with the recommendation or answer; include only meaningful alternatives.
6. **Act** — give the next concrete action or execute it when authorized.

Use tools only when freshness or factual accuracy materially affects the answer. If verification or interacting constraints become central, escalate rather than stretching Lite.

## Default output

- Answer or recommendation
- One or two decisive reasons
- Important caveat, if any
- Next action, if useful

Do not show the stage-by-stage trace unless the user requests an audit-relevant explanation.
