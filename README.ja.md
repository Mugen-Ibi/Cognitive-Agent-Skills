# Cognitive Agent Skills

[English](README.md)

ユーザー側の問題設定・探索・評価におけるボトルネックを軽減するための、小さな Human–AI 認知プロトコル群です。

AI がユーザーの最初の問題設定を越えて探索し、自らの提案を批判的に検討し、意思決定を左右する主張を検証したうえで、人間が扱える大きさの意思決定ブリーフへ圧縮することを目的としています。必要な深度が分からない場合は Router を入口として使い、適切な厳密さが明らかな場合は個別のプロトコルを直接指定します。

## 背景：人間の認知限界

人間の思考には、注意、ワーキングメモリ、時間、利用可能な知識の限界があります。また、問題を自分がすでに知っている概念の範囲で捉えやすいため、隠れた前提、未検討の選択肢、二次的な影響が最初の問題設定から抜け落ちることがあります。

したがって、ボトルネックは単に「答えを見つけること」だけではありません。次のような作業も人間側の大きな負荷になります。

- そもそも何を問題として捉えるべきかを発見する
- 最初の問題設定が妥当かを疑う
- 複数の説明や解決策を比較する
- どの主張を、どの程度まで検証すべきかを判断する
- 広い探索結果を、実際に判断できる大きさへ圧縮する

AI は探索範囲を広げられますが、構造を与えずに使うと、もっともらしい誤り、選択肢の過剰生成、最初の案への早すぎる収束、人間が評価しきれない長大な出力といった別の問題を生みます。推論量を増やすことも、それによって意思決定が変わらないなら常に有益とは限りません。

この Skill 群では、認知限界を個人の能力不足ではなく、Human–AI システムの設計上の制約として扱います。発見、再定義、探索、批判、検証、圧縮を、タスクに見合う深度で AI に委ねます。一方で、価値判断、リスクの受容、重大または不可逆な意思決定は人間が保持します。

## Skills

| Skill | 役割 |
|---|---|
| `cognitive-router` | 適切なプロトコルを選択し、実行中も厳密さを動的に引き上げ、または引き下げます。 |
| `cognitive-lite` | 低リスクでやり直しやすいタスク向けの高速なプロトコルです。 |
| `cognitive-standard` | 実質的な複数ステップの分析や意思決定に使う標準プロトコルです。 |
| `cognitive-high-precision` | 高い影響を持つ判断や公開品質の作業向けの、厳密で監査可能なプロトコルです。 |

## インストール

リポジトリをクローンします。

```bash
git clone https://github.com/Mugen-Ibi/Cognitive-Agent-Skills.git
```

使用する AI またはエージェント環境がサポートする方法で、`skills/` 配下の各ディレクトリをインストールしてください。Codex 互換のローカル環境では、各ディレクトリ名とその中の `SKILL.md` を維持したまま、設定済みの Skills ディレクトリへコピーします。

```text
<skills-directory>/
├── cognitive-router/
│   └── SKILL.md
├── cognitive-lite/
│   └── SKILL.md
├── cognitive-standard/
│   └── SKILL.md
└── cognitive-high-precision/
    └── SKILL.md
```

自動ルーティングを利用する場合は4つすべてをインストールします。特定のプロトコルを直接呼び出す運用なら、子 Skill のみをインストールすることもできます。

Skill から別の Skill を呼び出せるかどうかは実行環境に依存します。そのため Router は、sibling Skill の呼び出しが可能な場合は選択した Skill へ処理を移譲し、利用できない場合は選択プロトコルの意味論を Router 自身が fallback 実行します。

## 使い方

必要な分析深度をシステムに選ばせる場合は、`cognitive-router` を使います。

```text
cognitive-router を使って、この移行計画を評価し、最も安全な進め方を提案してください。
```

必要な厳密さが分かっている場合は、子プロトコルを直接指定します。

```text
cognitive-lite を使って、この2つのやり直し可能な選択肢から選んでください。
```

```text
cognitive-standard を使って、これらのアーキテクチャ案を比較してください。
```

```text
cognitive-high-precision を使って、公開予定の研究方法をレビューしてください。
```

通常、各プロトコルは内部探索の逐語的な記録ではなく、結論、根拠、前提、トレードオフ、次の行動を提示します。

## 使用例

### すぐに修正できる小さな判断

```text
cognitive-router を使って、この小さな社内スクリプトの命名規則を選んでください。
```

想定ルート：`cognitive-lite`。誤った場合の影響と修正コストが小さいためです。

### 複数の制約が関わるプロジェクト判断

```text
cognitive-router を使って、プロダクトの3つの認証アーキテクチャを比較してください。
```

想定ルート：`cognitive-standard`。制約、トレードオフ、実装への影響、外部検証が重要になるためです。

### 公開品質の評価

```text
cognitive-router を使って、投稿前の論文の方法論と根拠を監査してください。
```

想定ルート：`cognitive-high-precision`。再現性、一次資料、敵対的レビュー、監査可能性が必要になるためです。

## ルーティング例

| タスク | 標準的なルート | 理由 |
|---|---|---|
| ワークショップ名の案出し | Lite | 影響が小さく、容易に修正できる |
| 研究課題の選択 | Standard | 複数の問題設定と実質的なトレードオフがある |
| 公開予定の実験方法の確定 | High Precision | 高い根拠水準と再現性が必要になる |
| 使い捨てプロトタイプの設計 | Lite または Standard | 複雑でも、やり直しやすければ必要な厳密さは抑えられる |
| 単純だが安全性に関わる質問 | High Precision | 重大な結果を招く要因は、複雑性が低くても優先される |

ルーティングは動的です。矛盾する証拠、隠れた依存関係、想定以上の誤りのコストが見つかれば、より厳密なプロトコルへ移行します。問題が限定され、追加分析の期待価値が低くなれば、厳密さを引き下げます。1つの依頼に異なる性質の作業が含まれる場合は、構成要素ごとに異なるプロトコルを使うこともできます。

## プロトコルの選択

適切な分析深度が事前に分からない場合は、`cognitive-router` を標準の入口として使用します。

Router は、結果の重大性、可逆性、複雑性、不確実性、根拠の必要水準、ユーザーが明示した厳密さを評価します。実行中に新しい情報が得られた場合も、追加の厳密さが持つ期待価値に応じてエスカレーションまたはダウングレードします。

## 設計思想

- **最大の厳密さではなく、適切な厳密さ。** 意思決定品質の期待値から、認知・計算・時間コストを差し引いた価値を最適化します。
- **最初の問題設定は仮説。** 隠れた前提、別の問題設定、意思決定を変え得る見落としを探します。
- **決定する前に攻撃する。** 有力な提案を、反例、失敗シナリオ、別の因果説明に照らして検討します。
- **意思決定を変え得る主張を検証する。** 結果の重大性、不確実性、可逆性に応じて検証コストを配分します。
- **人間が判断できる大きさへ圧縮する。** 広い探索を、簡潔で追跡可能な意思決定ブリーフへ変換します。
- **重大な選択は人間が所有する。** 価値判断、リスクの受容、不可逆なコミットメントはユーザーに残します。
- **実行中も深度を調整する。** タスクの実像が明らかになるにつれて、厳密さを引き上げ、または引き下げます。

User Intent

    v

    |

             |

sibling Skill の呼び出しが可能な場合、Router は選択した子 Skill へ実行を移譲します。利用できない場合は、同じプロトコルの意味論を Router 自身が fallback として実行します。

## バージョニング

正式なリリース開始後は、Semantic Versioning の採用を想定しています。

- **Patch**：プロトコルの動作を変更しない文言の明確化や書式修正
- **Minor**：後方互換性のある指針、ルーティング基準、任意機能の追加
- **Major**：既存の利用方法に影響し得るプロトコルの意味論、出力契約、ルーティング動作の変更

最初のタグ付きリリースまでは、`main` ブランチをプレリリースとして扱ってください。内容は今後変更される可能性があります。
